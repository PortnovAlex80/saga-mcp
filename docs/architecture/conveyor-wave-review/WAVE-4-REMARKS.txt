ВОЛНА 4. ОДИН ДИСПЕТЧЕР И ГЛОБАЛЬНАЯ КОНКУРЕНТНОСТЬ

Статус проверки: не завершено.

Основные замечания:

1. В кодовой базе остаются несколько путей запуска: Flow LM nodes, Development implementation cards, legacy orchestration и отдельные module loops. Наличие общего dispatch service не доказывает, что остальные циклы больше не запускают рабочих самостоятельно.

2. Глобальный предел конкурентности должен принадлежать одному application service или semaphore. Локальные значения concurrency в модулях и runner-конфигурации могут суммарно превысить N.

3. Последовательные await-циклы необходимо отличить от настоящего bounded worker pool. Тест должен доказывать временное перекрытие двух execution при N больше или равно 2.

4. Не закрыты единым контрактом ошибки запуска, cancellation и shutdown. Особо опасен сценарий: карточка уже assigned, а launcher упал до появления живого процесса.

5. Не доказано, что shutdown освобождает все назначенные, но фактически не запущенные карточки и не оставляет orphan execution.

Исследовать и исправить:

Построить список всех production callers WorkerLauncherPort.start и всех циклов, выбирающих следующую работу. Маршрутизировать их через один dispatch application service. Удалить или заблокировать локальные concurrency options. Реализовать общий bounded pool с одним бюджетом. Определить атомарные реакции на launch failure, cancellation timeout и shutdown. Добавить тесты с управляемыми promises и счётчиком одновременно работающих запусков.

Критерий завершения:

Во всём runtime существует один владелец dispatch loop и один глобальный concurrency budget. При N=2 две карточки реально выполняются одновременно. Максимальное число активных workers никогда не превышает N при смешанном запуске Flow и Development. Ошибка старта и shutdown возвращают незапущенную карточку в очередь с audit event.
