ВОЛНА 8. ПРОДАКШН V2 CUTOVER — БЛОКЕРЫ

Статус проверки: переход НЕ завершён. Тесты зелёные, потому что production
фактически не входит в v2-путь; blockers остаются скрытыми.

BLOCKER 1. Production не входит в v2-путь.
Четыре executor-а создаются без v2 в product-lifecycle-runtime.ts:540. Fresh
run требует уже существующий v2-marker, который мог бы создать только сам
v2-путь (generic-flow-executor.ts:408, helper:1281). Поэтому ModuleCompletion
сейчас не сохраняется production-путём, а crash между settlement и terminal
emitter теряет сертификат.

BLOCKER 2. Включение v2 сразу сломает Delivery и Formalization.
Они создают настоящий циклический объект completion → envelope → completion
(delivery-installation.ts:546, formalization-installation.ts:1701). Repository
выполняет JSON.stringify(completion) в sqlite-node-run-repository.ts:414, что
даст «Converting circular structure to JSON».

HIGH 3. Terminal ModuleCompletion всё ещё необязателен.
Executor завершает ProcessRun с certificate=null, если completion отсутствует
(generic-flow-executor.ts:319). Delivery и Formalization проглатывают ошибку
выдачи сертификата и возвращают completion: undefined (delivery-installation.ts
:699, formalization-installation.ts:1573). После удаления magic fallback это
уже не восстановимый путь.

HIGH 4. Durable completion не имеет собственной identity/integrity.
Хранится только JSON, без completion_hash; повреждённый JSON молча
превращается в null (sqlite-node-run-repository.ts:224). При settlement
проверяется только совпадение outcome, но не terminal, форма ProductRef и
digest (generic-flow-executor.ts:1476).

HIGH 5. Reaper принимает две опасные противоположные реакции.
Живой локальный процесс с истёкшей lease освобождается без verified kill
(stuck-policy.ts:207). При доказанном PID reuse карточка, наоборот, никогда
не освобождается (stuck-policy.ts:288). Первое допускает двух рабочих у
одного стола, второе навсегда блокирует карточку.

MEDIUM 6. Single-writer пока не достигнут.
markExecutionExited напрямую пишет execution и task (worker-executions.ts:190).
Gate сознательно разрешает это как временное исключение (atomic-release.ts:13).
Это противоречит документу, где close callback и reaper должны использовать
один атомарный механизм.

MEDIUM 7. Нулевая dependency-ratchet метрика скрывает runtime-зависимость.
Discovery динамически импортирует Saga3 application service именно для обхода
статического графа (discovery-installation.ts:139). Production composition
root не передаёт settlementService (product-lifecycle-runtime.ts:452).
Формально тест зелёный, фактически bounded contexts связаны.

MEDIUM 8. Документация переоценивает завершённость.
ARCHITECTURE.md:49 всё ещё заявляет 14 global ports, хотя оставлен один.
Новый обзор признаёт type-cycle лишь как smell, но не замечает реальные
циклические объекты (BIRDS-EYE-VIEW.md:183).

ВЕРДИКТ

Переход движется в правильную сторону: static dependency allowlist равен
нулю, magic-bindings readers удалены, модульные реализации больше не
импортируют SQLite напрямую, pure reaper policy выделена. Но переход нельзя
принимать как завершённый: durable ModuleCompletion cutover фактически не
включён.

ИСПРАВЛЯТЬ В ТАКОМ ПОРЯДКЕ:

1. Сделать модель acyclic: удалить ProcessModuleOutputEnvelope.completion;
   оставить ModuleCompletion.outputEnvelope.
2. Исправить bootstrap v2 и подключить его в production composition root.
3. Добавить реальный SQLite end-to-end: четыре модуля плюс crash после
   settlement.
4. Сделать terminal completion обязательным и валидируемым, добавить digest.
5. Исправить reaper decision matrix и затем закрыть single-writer исключение.
6. Удалить dynamic bridge и синхронизировать документы.

Проверки сейчас зелёные: npm test — 3291 pass, 37 skip, 0 fail;
npm run test:architecture также прошёл. Именно отсутствие production-v2
сценария позволяет блокерам оставаться зелёными.
