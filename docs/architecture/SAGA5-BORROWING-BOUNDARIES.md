# Что мы заимствуем, а что отказываемся заимствовать

- **Статус:** разбор внешнего предложения о «пяти ортогональных слоях»
  (n8n / Temporal / DeepSeek Harness / Saga Desk / Kanban), 2026-08-31.
- **Зачем:** каждое заимствование обязано назвать проблему, которую оно
  решает, и цену. Иначе saga5 повторит путь saga4, где каждый разумный слой
  был разумен по отдельности.

---

## 1. Что в предложении верно и уже сделано

| Тезис | Статус |
|---|---|
| «n8n даёт форму графа, не экосистему» | ✅ так и есть: `{nodes, connections}`, ядро не знает семантики цехов |
| «Temporal даёт физику времени: lease, heartbeat, типизированные таймауты, ретраи, восстановление из журнала» | ✅ реализовано, `waiting` никогда не превращается в `crashed` |
| «Kanban ничего не хранит; карточка — проекция журнала» | ✅ `src/kernel/projection.ts`, ноль новых таблиц |
| «Desk — доменный объект, не UI-понятие» | ✅ ревизия стола = запечатанное множество дайджестов, живёт в ядре |
| «Не зависеть от внутренностей стороннего harness» | ✅ и мы идём дальше — см. §2 |

Отдельно стоит выделить самую сильную мысль предложения:

> «Значительная часть ума переезжает из МОДЕЛИ в ГРАФ + ПРОМПТЫ + ГЕЙТЫ +
> АРТЕФАКТЫ.»

Это точное описание того, ради чего saga5 существует. Слабая модель + узкий
промпт + маленький вход + исполнимая приёмка даёт результат, который сильная
модель с пятнадцатью страницами инструкций даёт нестабильно.

**Но это гипотеза, а не архитектурное решение** — см. §4.

## 2. Что мы отказываемся заимствовать: «Worker Harness» как слой плагинов

Предложение вводит пятый слой:

```
Worker Harness: Model Adapter │ Tool Adapter │ Sandbox Adapter │ Skill │ Trace
```

**Это единственный пункт, который прямо ведёт обратно в saga4, и мы его не
берём.** Причины по порядку.

### 2.1 Шов уже есть, и он в одну строку

Узел saga5 уже не знает, кто физически выполнил работу: воркер выбирает
исполнителя по `mode`.

```
mode: 'echo'      — скриптованный воркер (детерминированный, без сети)
mode: 'opencode'  — CLI (сейчас Z.AI coding plan)
mode: 'api'       — любой OpenAI-совместимый endpoint (LM Studio и прочие)
```

Добавить LM Studio — это `LLM_BASE_URL`, а не новый слой. Абстракция
`AgentAdapter` с реестром не даст ни одного нового пользователя сверх того,
что уже даёт одно поле. Плата за неё — реестр, жизненный цикл, версии
контракта, тесты соответствия адаптеров. Ровно так saga4 обзавелась
установкой пакетов и пинами дайджестов.

**Правило:** абстракция вводится на третьем реальном потребителе, а не на
первом воображаемом.

### 2.2 «Tool Adapter» ломает границу эффекта

Инструменты, которые **читают**, безопасны — мы их добавили как `tools:
[{kind:'attach'}]` (принятый артефакт подкладывается в промпт).

Инструменты, которые **пишут**, — нет. Если воркер внутри своего вызова
может дёрнуть git или запустить тесты, то леджер эффектов перестаёт быть
авторитетом: внешнее изменение произошло, а idempotency-ключа и квитанции для
него нет. Это противоречит и самому предложению («Model НЕ пишет workflow
state»), и нормативному правилу конвейера: воркер может *описать* желаемое
состояние, но не может выдать себе право на эффект.

Наш ответ — узел `command`: побочное действие планирует **ядро**, оно
получает таймаут, попытку, исход и квитанцию, а его результат становится
материалом, который судит гейт. То же и с песочницей: «sandbox» — это `cwd`
узла (`workdir: 'items'` кладёт кандидата во временный каталог), а не слой.

### 2.3 «Execution Trace» у нас уже есть и в правильном месте

Журнал прогона + фазовый лог воркера + расход токенов в `execution.completed`.
Заводить для этого плагин нечего.

## 3. Где предложение неточно: «Desk не знает, Claude это был или Qwen»

Как запрет — **неверно**, и слепое его исполнение уничтожило бы полезное.
Item несёт `model`, а попытка несёт `usage`: без этого нельзя ни считать
стоимость, ни ответить на вопрос «какая модель произвела этот мусор».

Точная формулировка инварианта:

> Провенанс попытки (модель, токены, стоимость) записывать **обязательно**.
> Ни одно **решение** не имеет права ветвиться по модели: ни гейт, ни выбор
> следующего узла, ни идентичность материала.

Первое — это память завода. Второе — это то, что нельзя нарушать. Смешивать
их в один запрет вредно.

## 4. Где предложение выдаёт гипотезу за архитектуру

Цепочка «Extract facts → actors → entities → relationships → questions →
rules → FR → NFR → UC → AC → cross-check → assemble» подана как готовое
решение. Считаем цену:

- 12 столов = 12 вызовов модели = 12 гейтов = 12 мест отказа;
- каждый следующий стол читает накопленные артефакты, поэтому суммарные
  входные токены **растут**, а не падают (замер: один вызов `srs` — 8191
  входных токенов; двенадцать таких вызовов не станут дешевле одного);
- каждая передача — потеря контекста, которую приходится компенсировать
  промптом.

Это может окупиться на слабой модели и не окупиться на сильной. Правильный
ответ — **не решать это в архитектуре**. Благодаря сборке цеха из столов
(`src/desks.ts`) обе версии выражаются как ДАННЫЕ:

```
srs_short:  [srs]
srs_long:   [facts, actors, entities, relations, questions, rules,
             fr, nfr, uc, ac, crosscheck, assemble]
```

Запустить обе на одной идее и сравнить (время, токены, число доработок,
исход дымовой проверки) — вопрос вечера, а не редизайна. Пока замера нет,
менять умолчание нельзя.

## 5. Что берём: шесть запретов как тесты

Предложение верно предлагает превратить границы в fitness-тесты. Берём пять
как есть и один — в исправленной формулировке (§3):

| Запрет | Как проверяется |
|---|---|
| Доска не решает, что запускать | у доски нет пути записи, кроме `operator.resolved` |
| Воркер не выбирает следующий узел | claim делает мост, переход решает ядро |
| Модель не пишет состояние прогона | воркер может только settle своей попытки под lease |
| Граф не хранит runtime-состояние | в `graph_json` только декларация; `position` игнорируется ядром |
| Исполнение не является материалом | идентичность материала = дайджест содержимого (ADR-053) |
| Решение не ветвится по модели *(исправлено)* | провенанс пишем; ни один гейт/переход его не читает |

Реализованы в `tests/boundaries.test.mjs`.

---

## 6. Итог

Берём: граф (n8n), физику времени (Temporal), стол и материал (saga),
проекции для человека (канбан + канвас), и явную цель — вынести ум из модели
в граф, промпты, гейты и артефакты.

Не берём: harness как слой плагинов, инструменты с правом записи внутри
вызова модели, песочницу как отдельную подсистему, и заранее выбранную
длинную цепочку столов.

Причина отказов одна и та же: **каждый из этих слоёв разумен сам по себе, и
именно поэтому saga4 набрала их девять.** Слой добавляется тогда, когда без
него нельзя выразить реальный цех, а не когда он красиво рисуется на схеме.
