# PROVIDER-RETRY — progressive retry на 429/5xx в шиме

**Автор идеи:** оператор («если система видит 429/500 — ретрай 1→2→4→8→16…, до 10 попыток»).
**Статус:** дизайн-исследование; к реализации в шиме после терминала stage-11.

## Ответы на четыре вопроса

**1. Видит ли система 429/500? — НЕТ.** Единственный классификатор ошибок во всей
цепочке воркер→завод матчит два кода подготовки репо-деска. `worker.exit` в журнале
несёт exit_code+длительность — 429 и OOM неотличимы. UI даже УТВЕРЖДАЕТ
существование 429-шедулера, которого нет в коде (board-render:938; скилл saga-patrol
ссылается на несуществующий detectRateLimits). При этом приватный лог opencode
РЕАЛЬНО содержит класс (AI_APICallError socket closed ×5 инстансов) — невидимый заводу.

**2. Что происходит с умершим от 429 сегодня?** Ре-спавн за ~300мс, БЕЗ бэкоффа.
Единственное демпфирование — бюджет эпохи (3 смерти подряд = окно молотения) +
бэкофф 1→15мн МЕЖДУ эпохами. ADR-075 бэкофф НЕ применяется к смертям воркеров.

**3. Правильная точка — ШИМ** (claude-shim.mjs): он владеет жизненным циклом,
фабрика не узнаёт о транзиенте (ноль изменений завода, ноль расхода бюджета).
Предусловия: stdio→pipes+tee (сейчас inherit — шим слеп), heartbeat каждые ≤30с
сна (иначе рипер убьёт лестницу по STUCK_SILENCE: тишина копится ПОПЫТКАМИ).
Дискриминатор консервативный: retryable-текст (429/rate/overloaded/5xx/socket
closed/ECONNRESET/ETIMEDOUT) ИЛИ exit≠0+тишина+умер ДО первого ⚙-инструмента
(доказуемо без сайд-эффектов). После `saga_worker_done` — НИКОГДА (дабл-комплит).
До первого инструмента — полная лестница; после — сокращённая (2-3): тот же класс
риска, что заводская рекавери уже принимает.
Кэп: **6-8 попыток, макс сон 128-256с** (не 512с/10) — дольше = outage, и
эпох-машина лучший инструмент. Учёт-невидимо, лог-видимо (stderr→JSONL→/api/worker/tail).

**4. Контрфакт по живым прогонам — честно: НОЛЬ реальных 429/5xx в обоих прогонах.**
Все 3 смерти — транспортный потолок ~20-30мин (тишина посреди работы, без текста
ошибки). Строгий дискриминатор ретраил бы 0 из 3; фактическая рекавери (300мс +
свежий воркер) завершила обе карты БЫСТРЕЕ предложенной лестницы. Ценность
предложения —Future-proofing на класс быстрых 429-штормов (умирают до первого
инструмента), которого в данных ещё нет.

## Почему не другие точки

- Раннер: свяжет общий раннер с форматом stderr конкретного бэкенда.
- Ре-диспетч: защищает сессию фабрики, теряет прогресс карточки, нужен классификатор
  (дополнительный шов — комплементарно при хронических outage, там же circuit breaker).
- Конфиг opencode: пуст ($schema only), рычага нет; внутренняя устойчивость opencode
  непрозрачна (иногда log-and-continue, иногда молчаливый exit 1).

## Мёртвый код найден

syncSleep («pump retry back-off») и consecutiveSpawnFailures в раннере —
вестигии старого спавн-шторма; одкарточного pump больше нет. Удалить при случае.
