# PAUSE/START — дизайн настоящей паузы (graceful-drain)

**Автор идеи:** оператор («паузы нет — воркер выгоняется; старт должен вернуть в точки найма»).
**Статус:** дизайн согласован (механика старта + механика стопа + дизайн-сравнение);
к реализации — после терминала stage-11.

## Установленные факты (по коду и живому прогону)

1. **Панель ⏸ сегодня — даже НЕ soft-stop**: она зовёт killEngineTree напрямую
   (`/api/factory/stop` → engine-administration.stop) — без fence, без отмотки,
   без holds. Трупы `running`-строк блокируют клейм до свипа. (CLI soft-stop —
   другой, честный путь, но к панели не подключён.)
2. **▶ никогда не снимает holds** (единственный релизер — `factory.mjs unpark`)
   → «остановленный завод, который выглядит запущенным» — точное поведение:
   движок resume'ит, клеймит 0, умирает 'paused' после 3-стрика.
3. **Цена сегодняшнего ⏸** (по stage-11): min 2.1 / median 9.2 / **mean 10.3 /
   max 30.0 мин** потерянного хода на каждого активного воркера; два внутри-прогонных
   килла уже стоили 21.4 и 30.0 минут (наблюдали в журнале как reaped).
4. Один запуск = одна карточка («one launch = one card») — воркер сам НИКОГДА не
   клеймит следующую; единственный наниматель — движок. Значит **очередь можно
   оградить, не трогая воркеров**: они само-ограничены.

## Выбор: graceful-drain (вариант A)

Сравнили: A drain (0 потерь токенов) / B checkpoint-стоп (НЕ спасает mid-turn ход —
только узловые результаты; «ложный комфорт») / C как сегодня (гарантированные потери).
**A побеждает** — и он на ~80% собран из существующих механизмов:

- Дождь уже работает: `capacity_blocked` + `Promise.race(active)` (dispatch-loop
  :438-452) — хвост дожидающийся активных.
- Ограда очереди уже есть: claim-SQL чтит `factory_operator_holds`
  (work-assignment-core :479-489) — project-scope hold держит очередь durably,
  НЕ мешая активным воркерам (holds консультируются только на клейме).
- Движок сам паркуется: пустая диспетчеризация → 3-стрик → exit-2 'paused'
  (orchestrate-cli :578-589) — слот launch освобождается для следующего ▶.

## MVP — три куска, ни одного нового физического закона

1. **⏸** пишет project-scope operator hold (ограда очереди) — опционально
   `capacity_blocked`-условие в startOne; движок до-дренивает и сам выходит
   exit-2 paused.
2. **▶ = releaseOperatorHolds(project) + существующий resume-spawn** — это заодно
   чинит ловушку «looks-started» (главный дефект пары кнопок).
3. **UI**: двухфазная кнопка — «⏳ дожидаемся N воркеров» (poll /api/workers/active,
   прецедент рендера pipeline.js:221-248) → «на паузе»; сегодняшний жёсткий стоп
   остаётся ВТОРЫМ явным действием (fallback для зависшего воркера — у дожина
   должен быть дедлайн, backstop = cancel-grace kill).

## Чего A НЕ решает (честно)

Не мгновенна (ограничена самым длинным живым ходом, ≤30 мин наблюдено); зависший
воркер стопорит дожин (нужен дедлайн + жёсткий стоп вторым кликом); движок всё равно
умирает/рождается заново (бесплатно — durable state); model-слоты заняты до конца ходов.

## Слепой случай (наш, factory.mjs-движок)

Durable hold делает слепой ⏸ осмысленным: очередь ограждена независимо от
controls-строки; гвард B-006 v2 на фронте уже показывает честный ⏸. Для полного
останова движка-зомби остаётся ручной путь: stop → kill процесс-сканом
(_kill-frozen.ps1) → unpark → resume (после ≥30с lease).

## Поправка по проводке (стоп-механика, финальный аудит)

Панельный ⏸ НЕ подключён к soft-stop: `/api/factory/stop` →
`EngineProcessAdministration.stop` → killEngineTree (best-effort, проглатывает
ошибки) + штамп controls 'stopped'. На слепых controls матчеры киллера не совпадают
НИ С ЧЕМ (легаси-позиционный — никогда; orphan ищет 'project_id=' в argv, а промпт
идёт через stdin) → нажатие = штамп 'stopped' при живом заводе = лживый no-op.
Настоящий протокол (fence+void+rewind+holds+checkpoint) живёт ТОЛЬКО в
`factory.mjs stop|unpark` (operator-soft-stop.ts). Коммит fabf50ab ошибочно
назвал панельный путь soft-stop — это было устремление, не проводка; фронт
поправлен говорить правду (кнопка-пустышка с путём CLI) до переподключения
кнопки к настоящему стопу как части этого дизайна.
