## Системные слабости (топ-3)

1. **Ноль измеримости успеха во всей партии** — в схеме proposal нет поля
   success measures, и никто не компенсировал. W2 будет выдумывать AC-метрики с нуля.
2. **problem_statement вырождается в пересказ решения**, когда идея — билд-спека
   (stopwatch/snake/kanban/themes).
3. **Шаблонные риски/unknowns** (localStorage-квота ~10/14, WCAG 8, mobile 9) —
   гейт не отличает шум от содержания.

## Сильные стороны (топ-3)

1. **Дисциплина покрытия почти идеальна**: 12/14 — 100% требований с точными
   параметрами (20×20, шаг 1/5/10, слайдер 0–30, 25/5/15, 30–120 баров, ±6 мес…).
2. **Доменно-острые технические риски**: FOUC, autoplay-политики Web Audio,
   отсутствие touch у HTML5 DnD, двухприближённость Гомана, дрейф performance.now(),
   floating-point в деньгах.
3. **Честная эпистемика**: unknowns — настоящие вопросы; assumptions отделены;
   «Adoption: None» вместо выдуманного риска.

## Вердикт для W2

**Условно пригодны** (11–12/14 — напрямую). Чинить первыми:
1) впрыснуть метрики успеха (поле в схему discovery-proposal.v1 или гейт-критерий W2);
2) погасить платформенные unknowns (P03 tips, P11 markdown — снять выдуманную
   библиотеку, вернуть escape вместо sanitize);
3) mars: перенести входные ограничения из observed_context в candidate_scope;
4) дедуплицировать шаблонные риски.

## Портрет автора (по артефактам, вслепую)

избегает квантификации успеха, шаблонит хвостовые риски.»
