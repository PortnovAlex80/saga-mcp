# SNAPSHOT-TEST — детерминированный ре-ран завода из захваченного материала

**Автор идеи:** оператор (2026-08-19). **Статус:** дизайн согласован тремя
расследованиями (архитектура шва, достаточность материала, replay-пригодность);
к реализации — после терминала живого прогона stage-11.

## Суть

Зачем в тестах вызывать реальную ЛЛМ ради текста? Весь выход модели уже
захвачен (артефакты, продукты, вердикты — с хешами). Скрипт-двойник читает
корпус и проигрывает инструментные вызовы через настоящий шов. Хеши считает
фабрика от текста → canned-текст даёт детерминированные хеши автоматически;
«как же хеш» — не вопрос.

## Пять принципов (из критики идеи — обязательны)

1. **Корпус = функция отклика, не мешок текстов.** Проиндексирован по веткам
   сценария (happy, отвергнуто-v1, исправлено-v2, вердикты ревьюера) — ремонт-
   петли захваченных прогонов (use-cases reject→fix, планировщик 15→5) дают
   ветки, которые рука не напишет.
2. **Мандат: тест ЗАВОДА, не воркера.** Комплайнс модели здесь непроверяем
   по построению; это регрессия машины. Живой прогон — валидация воркера.
3. **Ассерты только контент-класса.** Хеши артефактов, дайджесты продуктов,
   байт-сравнение капсульных payload, вердикты, нормализованные
   последовательности видов журнала. Run-класс идентичностей (execution ids,
   projectId-ключи) — за скобками: капсулы DB-локальны (доказано аудитом).
4. **Двойник через настоящий шов с провенансом.** Scripted-executor спавнит
   настоящего воркера с SAGA_MANAGED_EXECUTION-контрактом — не обход фабрики.
5. **Граница задокументирована:** сменка поведения РЕАЛЬНЫХ воркеров корпусом
   невидима; он ловит только невалидацию canned-поведения.

## Архитектура (из отчёта архитектора)

- **Шов:** factory-contract scripted-executor — настоящий orchestrate-cli,
   настоящий MCP-гейтвей (stdio, тот же JSON-RPC), настоящий провенанс/леджер,
   настоящие дески. НЕ in-process хендлеры (теряют физические теоремы).
- **Компилятор** `tools/compile-run-tape.mjs`: снапшот + воркспейсы + корпус →
   `scenario-tape.json/.mjs` + `expectations.json`. Шаги: `call` (payload =
   ссылка на корпус), `read` (order-preserving), `assert_input` (fail-closed).
   Выходы — только корпус (fail-closed сервер `tests/mock-claude/corpus.mjs`);
   run-локальные идентичности — `$.`-биндинги в ран-тайме.
- **Диффер:** 9 групп ассертов (выход/без-сирот; исходы; последовательность
   вердиктов; топология кандидат-сетов; K13-идентичности; капсулы байт-в-байт;
   дайджесты сабмитов; нормализованный журнал видов; invocation-ledger 1:1).
- **Капсульный реплей = оракул взаимной консистентности:** скриптованная
   имитация и капсульная реконструкция обязаны сойтись на одном корпусе.
- **Хуки:** v1 не гоняем (наблюдатели модели, авторитета не пишут); опционально
   v2-шаг `hook:'post-tool-use'` с захваченными tool_response.

## Достаточность материала (из отчёта археолога)

Первый этап (Discovery, карты 1-2) восстанавливается **полностью, сегодня**:
каждый вход машины состояний захвачен с тройной избыточностью и сверков хешей
(call-файл == строка лога == строка БД). Formalization: артефакты file_backed,
тела на диске, все 12 sha256 совпали с content_hash. Провал-карты воркеров —
ANSI-рендеры, но `⚙ saga_<tool> {json}`-строки парсятся регексом (проверено).

**Единственное добавление захвата, которое нужно:** событие `tool.call` в
журнале на границе диспетчера/MCP (имя + полные аргументы + ординал
исполнения) + заполнение пустующей `factory_call_instances` тем же крючком —
после этого журнал самодостаточен, зависимость от живых логов исчезает.

## Найденные дефекты (чинить в кампании)

- **SNAP-1 (баг моего снапшот-инструмента):** `capture-run-snapshot.mjs`
  скопировал ЧУЖИЕ board-каталоги (`board-1-2900-*` утреннего движка) вместо
  логов текущего прогона (`stage11-logs/board-1-38000-*`) — выбор «новейших 3»
  по mtime взял устаревший корень. Чинить: фильтр по journal-зафиксированным
  `worker_executions.log_path`, не по догадке о корне.
- `worker.done` в журнале хранит `result_chars`, не текст — текст только в
  логах; закрывается тем же `tool.call`.

## Порядок строительства

1. Починить SNAP-1 (снапшот берёт логи по log_path из БД).
2. `tool.call` в журнале + `factory_call_instances` (одна точка append; в
   frozen-set ратчета диспетчер уже есть).
3. Компилятор ленты + интерпретатор `tapeScenario` (чистые добавления в tests/).
4. Драйвер `snapshot-replay.test.mjs` по образцу golden-path.
5. Ассерты инкрементально: вердикты → капсулы → журнал видов.
6. Взаимная консистентность: один модуль — и скриптом, и капсулой, сравнить.
