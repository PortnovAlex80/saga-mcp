# Development Capsule Qualification Plan

## SMART objective

By the end of this stage, Saga4 shall start a production-equivalent run at the
Development workshop from a content-addressed, independently verified
Discovery+Formalization capsule and complete three consecutive fresh
Development runs without operator repair. Every terminal claim, task-graph
edge, write scope, review blocker, verification result, readiness receipt and
integration effect shall be traceable in both independently derived forward
and reverse graphs. Blocking CI shall execute an externally defined Development
obligation universe, including all regressions found by Elite-9 and Stage-23.
This stage does not replace three later clean whole-conveyor qualifications.

## Established baseline

- [x] Stage-23 child was operator-paused, not terminal-failed.
- [x] Missing package-store startup failure is separated from workshop behavior.
- [x] Independently derived forward and reverse graphs were compared.
- [x] Named semantic gaps: homeless browser construction surfaces, the
      combat/navigation seam, future-owned tests demanded by an earlier
      reviewer, zero-AC implementation cards, and unscoped review findings.
- [x] Current scenario pack is classified honestly: its test validates
      declarations only, its driver is not blocking-hosted, and 17 of 35
      declared obligations remain open.

## Phase D0 — Freeze authoritative inputs

- [ ] Create a seed manifest binding capsule, certificate, DevelopmentCase,
      SRS, AC set, module installation, package-store, build, repository and
      base-commit digests.
- [ ] Copy SQLite with the backup API, verify package-store bytes, clone the
      product repository, and retarget only the copied repository row.
- [ ] Refuse missing/corrupt package bytes, digest drift, illegal parent state,
      active executions, lineage drift and sandbox reuse with typed reasons.
- [ ] Prove preparation does not mutate the golden source.

Exit: one command creates or refuses a fresh isolated Development run and emits
a complete preparation receipt.

## Phase D1 — Make both graphs executable

- [ ] Keep forward and reverse derivation independent.
- [ ] Introduce typed node, edge, authority and terminal-claim vocabularies.
- [ ] Reconcile by set equality, not prose assertions.
- [ ] Require every terminal construction claim to have an owned implementation
      surface and executable verifier.
- [ ] Require every implementation AC's SRS files, test layers and cross-module
      seams to lie in its scope or an explicitly ordered downstream owner.
- [ ] Route missing upstream surfaces to Formalization and reissue the capsule;
      never widen Development ad hoc.

Exit: the current Elite graph fails with named witnesses; a corrected graph
passes; deleting any required node or edge makes the blocking test fail.

## Phase D2 — Close the planner/worker/reviewer contract

- [ ] Encode one rule for infrastructure work: every implementation card has
      non-empty AC coverage, or infrastructure cards carry a distinct typed
      obligation identity. Prose and executable gate must agree.
- [ ] Reject structurally valid but jointly unsatisfiable task graphs.
- [ ] Require blocking findings to carry structured paths or an explicit
      non-file subject classification.
- [ ] Defer future-owned outside-scope findings, preserve in-scope blockers,
      and split mixed findings.
- [ ] Reject an out-of-scope first submission before claim history is mutated.
- [ ] Add production-sized combat and economy multi-round regressions.

Exit: exact Stage-23 counterexamples fail before worker-budget exhaustion and
lawful repairs converge on the same Workplace.

## Phase D3 — Restore whole-product construction ownership

- [ ] Add upstream construction surfaces for browser entry, static assets,
      bootstrap/build/start wiring and browser smoke behavior.
- [ ] Bind the combat/navigation seam through scope plus dependency or a later
      integration item.
- [ ] Own tests at the point where reviewers may lawfully require them, while
      candidate-wide verification stays independent.
- [ ] Reissue the W1+W2 capsule for upstream material defects.

Exit: a minimal served Node/browser product owns every source, test, build and
start surface and passes a real loopback/browser smoke check.

## Phase D4 — Replace the self-fulfilling scenario universe

- [ ] Define `DEVELOPMENT_OBLIGATION_UNIVERSE` independently of scenario files.
- [ ] Cover capsule ingress, planning, skills/tools/hooks, authoring, review,
      integration, recovery, faults, concurrency, freeze, readiness,
      verification, settlement and upstream repair routing.
- [ ] Execute every required scenario through canonical production composition
      on a fresh DB/repository/package-store copy.
- [ ] Add deliberately malformed inputs for every protection and prove the
      expected typed refusal plus the corresponding valid pass.
- [ ] Add noncompliant actors: omitted work, extra paths, narrowed claims, stale
      hashes, duplicate completion, prose-only review, long feedback and repair.
- [ ] Generate fresh normalized traces and reject snapshot-only evidence.

Exit: declared obligations equal demonstrated obligations, with no pending item
inside the blocking Development universe.

## Phase D5 — Make CI truth complete

- [ ] Host the scenario driver, not only its topology test.
- [ ] Classify every test as blocking, quarantined with owner/expiry, or an
      explicitly justified shadow.
- [ ] Add removal guards for driver, universe, corpus and evidence freshness.
- [ ] Revalidate quarantine on the current tree.
- [ ] Add a Windows lane or durable Windows evidence for Windows-only behavior.

Exit: an unclassified test, removed scenario, stale report or missing driver
fails CI.

## Phase D6 — Development soak and promotion

- [ ] Start every iteration from a new verified copy of the frozen kit.
- [ ] Convert every observed failure into a minimal regression before retrying.
- [ ] Achieve three consecutive terminal-success Development runs without
      operator intervention or oracle weakening.
- [ ] Preserve evidence bundles and compare normalized traces across all three.
- [ ] Promote the kit as the normal Development-first qualification path.
- [ ] Then resume three clean whole-conveyor Saga4 qualifications.

Exit: 3/3 fresh Development successes and no unresolved discrepancy between
graphs, obligation universe and observed traces.

## Stop conditions

- Do not count an operator stop as a factory failure.
- Do not repair missing upstream material inside a downstream card.
- Do not count a scenario merely because its description exists.
- Do not weaken an oracle, scope fence or review jurisdiction to obtain green.
- Do not modify a live Elite worktree or rebuild its dist.
