## БАГА #1 [BLOCKER] — AC settlement fails: fence mismatch после recovery

**Симптом:** Formalization завершается `failed`. Kernel `resolve-acceptance-contract`
выдаёт `"The acceptance execution persisted no canonical AC artifacts"` хотя 17 AC
artifacts созданы и прошли review.

**Корневая причина:** После recovery, `resolve-acceptance-contract` kernel ищет AC
managed-productions по execution fence **recovery-воркера** (task#6/#7, новый execution_id).
Но AC artifacts были записаны в `saga3_managed_artifact_productions` с execution fence
**исходного** producer'а (task#5, execution `exec-1-3444-1785389752934-1`).

**Почему fallback не спасает:** `readExecutionWrites` (formalization-installation.ts:987-1000)
имеет fallback на `listArtifactsForNodeInProcessRun` — но только когда **artifact AND trace
writes оба пустые** для текущего fence. Recovery-воркер добавляет trace writes в новом
execution → условие fallback не выполняется → artifact writes остаются пустыми.

**Где:**
- `src/process-modules/modules/formalization/formalization-installation.ts:517-533` —
  сообщение об ошибке
- `src/process-modules/modules/formalization/formalization-installation.ts:960-1048` —
  `readExecutionWrites` (fence query + fallback condition)
- `src/process-modules/persistence/sqlite-managed-production-ledger.ts:57-87` —
  `listArtifactsForExecution` (the fence columns)

**Доказательство (SQL):**
```
AC managed-productions: task_id=5, execution_id=exec-1-3444-1785389752934-1, intent_id=10399
Recovery resolver fence: task_id=6/7, execution_id=exec-1-3444-1785390592285/...
→ listArtifactsForExecution возвращает 0 rows
```

**Фикс (2 варианта):**
- **(a)** Fallback condition: срабатывать когда artifact writes пусты, **даже если trace
  writes есть** (trace writes в новом execution — это норма для recovery, они не должны
  блокировать поиск artifacts)
- **(b)** Recovery должен пере-регистрировать artifacts в новом execution (но это
  нарушает immutability managed-productions)

**Рекомендация:** Вариант (a) — минимальный, безопасный. Изменить условие в lines 987-1000
с `artifactWrites.length === 0 && traceWrites.length === 0` на `artifactWrites.length === 0`.

## БАГА #2 [LOW] — AC artifacts зависают в `draft` status

**Симптом:** После всего flow, 17 AC artifacts остаются `status=draft`. FR/NFR/RULE/UC/PRD
становятся `accepted`, но AC — нет.

**Корневая причина:** Это **следствие баги #1**. AC не проходят через `accept()` CAS в
`SqliteExactCandidateAcceptance` потому что kernel resolver не находит их (fence mismatch).
Если фикс #1 применить, AC пройдут accept и станут `accepted`.

**Где:**
- `src/process-modules/persistence/sqlite-exact-candidate-acceptance.ts:765-801` —
  `compareAndSetAccepted` (единственный механизм draft→accepted для formalization artifacts)
- `saga3_exact_candidate_acceptance_items` — нет ни одной AC записи (только UC/RULE/NFR)

**Статус:** Заблокирован багой #1. Не отдельный фикс.
