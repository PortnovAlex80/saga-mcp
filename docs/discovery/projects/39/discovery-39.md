# Discovery: Калькулятор точек окружности (Circle Points Calculator) — MVP

## Problem
В школьном курсе геометрии средних классов окружность определяется как
геометрическое место точек, равноудалённых от центра на расстояние R (радиус).
Эта алгебраическая конструкция (x² + y² = R², координаты, радиус) остаётся для
ученика абстрактной и слабо связанной с наглядным образом круга.

Идея продукта даёт простую, непосредственную возможность: ученик вводит радиус
числом, а приложение **вычисляет набор координат точек окружности** и
**отрисовывает круг** на экране. Так определение «окружность = множество точек»
становится осязаемым: ученик видит, как из дискретного набора вычисленных
координат складывается непрерывная фигура, и связывает радиус (число) с
геометрической картинкой и шкалой. Ценность — наглядность и связь
«число → координаты → рисунок» для аудитории, которой нужен конкретный образ, а
не только формула.

## Context
Проект абсолютно зелёный («greenfield»). По состоянию в трекере (Saga MCP):
- `repository_checkout_list({ project_id: 39 })` — 0 чекаутов;
- `artifact_list({ epic_id: 39 })` — 0 артефактов (нет PRD/UC/AC/FR);
- `note_list({ epic_id: 39 })` — 0 заметок.
Никакого существующего кода, дизайна или ранее принятых ограничений для этого
эпика нет. Полное описание продукта содержится целиком в задаче discovery
(objective): аудитория — школьники средних классов; платформа — веб-приложение
(браузер, без установки); поток — ввод радиуса → расчёт координат → отрисовка;
сложность — минимальный MVP. Привязанный репозиторий — `saga-mcp`, поэтому
документы discovery хранятся в `docs/discovery/projects/39/`. Сам продукт пока
не реализован.

## Users and Stakeholders
- Основной пользователь: школьник средних классов (примерно 11–15 лет,
  классы ~5–8), которому нужно наглядно увидеть связь радиуса и точек
  окружности.
- Вторичный пользователь: учитель математики/геометрии — может использовать
  приложение как классную демонстрацию.
- Заказчик / постановщик (product owner) — автор objective в задаче discovery;
  определяет границы MVP.

## Candidate Scope
Минимально полезный продукт — одностраничное клиентское веб-приложение без
бекенда, которое:
1. Показывает **одно числовое поле ввода радиуса** (положительное число) с
   понятной для ребёнка обратной связью при некорректном вводе (0, отрицательное,
   не число).
2. По введённому радиусу **вычисляет конечный набор (x, y)-координат точек
   окружности** (параметризация x = R·cos θ, y = R·sin θ для выборки углов
   θ ∈ [0, 2π), либо альтернативный школьный метод — см. Unknowns).
3. **Отрисовывает точки на экране** (canvas или SVG) так, что они визуально
   образуют круг; присутствуют оси координат и масштаб, чтобы радиус был
   зрительно проверяем.
Явно вне MVP: редактирование числа точек, анимация, несколько окружностей,
сохранение/экспорт, учётные записи пользователей, нативное мобильное приложение,
серверная часть.

## Assumptions
- Приложение работает целиком в браузере (только клиентский JS); бекенд для MVP
  не нужен.
- Стандартного рендеринга на canvas или SVG достаточно; WebGL не требуется.
- Ввод — одно положительное вещественное число (радиус); ноль/отрицательные/
  не-число обрабатываются дружелюбным сообщением.
- Для визуального приближения окружности достаточно конечной выборки точек
  (порядка десятков–сотен).
- Русскоязычный интерфейс допустим (аудитория — русскоязычные школьники); язык —
  второстепенная деталь.
- Привязанный репозиторий `saga-mcp` используется только как место хранения
  документации discovery; код продукта будет создан на последующих стадиях.

## Unknowns
- Точный класс/возраст и программный базис аудитории: знают ли ученики уже
  cos/sin? В русской школьной программе основы уравнения окружности появляются
  раньше, а cos/sin — в ~8–9 классе. Это влияет на выбор метода расчёта
  (cos/sin vs. школьный шаг через теорему Пифагора x = √(R² − y²)).
- Сколько точек сэмплить (визуальное качество vs. производительность vs.
  педагогический замысел «показать отдельные точки») — не задано.
- Нужно ли показывать вычисленные координаты также таблицей (читаемое
  «множество точек»), помимо графика — objective упоминает «набор координат»,
  что может трактоваться двояко.
- Желаемый визуальный стиль / брендинг не задан.
- Должно ли приложение работать офлайн / быть устанавливаемым (PWA) — не
  указано.
- Целевое место развёртывания (хостинг веб-приложения) не определено.

## Risks
- Педагогическое несоответствие: если аудитория — 5–7 классы и cos/sin ещё не
  изучены, этап «расчёт координат» может запутать, а не прояснить. Смягчение:
  согласовать метод расчёта с аудиторией на стадии UC/AC.
- Двусмысленность «точек окружности»: дискретная выборка для отрисовки vs.
  точный «список координат» как результат — разные интерпретации дают разный UI.
  Нужно зафиксировать на стадии формализации.
- Расползание скоупа: «калькулятор точек» может разрастись в полноценный
  геометрический инструмент (несколько фигур, анимация, экспорт). MVP должен
  оставаться минимальным.
- Крайние случаи рендеринга/производительности при очень большом радиусе или
  очень плотной выборке точек.
- Юзабилити для детей: крупный ввод, понятная обратная связь — требуется
  внимание, но не блокер.

## Recommendation: go
Задача понятна, MVP мал, хорошо ограничен и технически низкорискован: ключевой
поток (радиус → координаты → отрисовка) однозначен и реализуется полностью на
клиенте. Цель discovery — подтвердить понятность задачи и определить границы
MVP, и обе достигнуты. Рекомендую **go** (продолжать на стадию формализации —
UC/AC), вынося два открытых, но не блокирующих вопроса как Unknowns для
проработки на стадии UC/AC: (1) точный класс/базис аудитории для выбора метода
расчёта координат, (2) входит ли табличный вывод координат в MVP или вне его.
Ни один из них не блокирует старт; оба уточнимы при формализации требований.
