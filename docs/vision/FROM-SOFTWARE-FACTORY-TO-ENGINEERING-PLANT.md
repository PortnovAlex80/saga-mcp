# От software factory — к заводу регулируемой инженерии

Стратегический анализ: перенос конвейера saga на инженерное проектирование
(ж-д, ПГС, опоры, мосты) через замену цехов и MCP-инструментов.

- **Дата:** 2026-08-17
- **Повод:** проект GDesign (расчёт опор ОДН) как первый реальный
  инженерный кандидат на прогон через завод.
- **Статус:** видение и продуктовая гипотеза (не нормативный документ).
- **Метод:** сверка концепции (CONVEYOR-MENTAL-MODEL v5.2 + ADR) с кодом,
  разбор GDesign, исследование аналогов (deepseek-harness, EDA, Factory.ai,
  MetaGPT/ChatDev, Devin, Agent Teams, BIM-генерация).

---

## 1. Главный вывод

**Идейный замысел выдержан и подтверждён кодом: конвейер изначально
спроектирован профессие-агностичным, и GDesign — не «адаптация под
инженерию», а второй естественный incarnation той же нормативной модели.**

Три доказательства:

1. **Модель декларирует это явно.** §1: материал через границу воркера —
   «текст или content-addressed материал; proposal, PRD, SRS, source code,
   reviewer verdict и verification report различаются схемой, а не
   рантайм-механизмом». Расчётная модель, записка КР3-РР и чертёж
   вписываются в это определение без натяжек. §3 LEGO: «core runtime must
   not branch on workshop name or worker profession».
2. **Код это выполняет.** Все 4 цеха (discovery / formalization /
   development / delivery) — декларативные пакеты: manifest (pure data),
   contributions (output-contracts, acceptance-capabilities,
   tool-contributions, receipts), node protocols. Ядро
   (dispatcher/gate/replay/effects) не знает имени цеха. Verification-слой
   (`src/infrastructure/verification/`) — точка расширения, куда ложатся
   детерминированные инженерные провайдеры.
3. **GDesign независимо изобрёл ту же дисциплину.** Его собственная
   архитектура — это мини-конвейер: стадии S0–S10 с обязательными гейтами,
   иерархия авторитета (СП/СНиП + явные допущения → аналитика → независимо
   воспроизведённые таблицы → SCAD-свидетель → ручные расчёты →
   регрессии), CALCULATION_MATRIX (34 позиции C001–C034: входы, реализация,
   единицы, класс доказательства, статус), BUG_JOURNAL, ADR-001 «femdriver —
   зависимость для квалификации, не оракул; SCAD — внешний свидетель».
   Это дословно Cell/Gate/CheckProvider/RecoveryIssue/фитнес-функции.

Совпадение не случайное: и ПО-фабрика, и проектный институт решают одну
проблему — **как производить материал, которому можно доверять, силами
ненадёжных исполнителей**. Ответ в обоих случаях нормативный: рабочие
места, кандидаты, приёмка, запечатанные ревизии.

Что НЕ выдержано (по конформность-аудиту 2026-08-16, конец
CONVEYOR-MENTAL-MODEL): материальный авторитет ещё не полностью cutover —
settlement-швы формализации выбирают материал по epic-накоплению, а не по
точной ревизии рана; newest-wins капсульный биндер; resume-совместимость не
сверяет implementation-дайджесты хендлеров. Для инженерии это опаснее, чем
для ПО: цена ошибочной авторитетной выборки — подписанный том с чужими
нагрузками. **Завершение ADR-053/073 — предусловие инженерного завода, а
не параллельная работа.**

## 2. Карта аналогов: ниша пуста

| Система | Что есть | Чего нет у них / есть у нас |
|---|---|---|
| deepseek-harness (~130k★) | Композитуемый рантайм одного агента, «всё — плагин»; append-only session log как рантайм-инвариант | Владелец работы — сессия/агент. Нет производства: цехов, кандидатов, приёмки |
| EDA RTL→GDSII (+DSO.ai/Cerebrus) | Эталон конвейера: форматы-контракты (GDSII/LEF/DEF), tool-based signoff, запечатанный PDK | Жёстко один домен и вендорский стек; LLM-гибкости нет |
| Factory.ai «Software Factories» | Ближайшая метафора: droids, Missions, Knowledge Grid, полный SDLC | Нет модели материала: ревизия = git-коммит кода; workplace как нормативный владелец отсутствует |
| MetaGPT / ChatDev | Конвейер ролей, «assembly line paradigm» | Приёмка = убедить соседа; артефакты — файлы в контексте, перегенерируются каждый прогон |
| AutoGen / CrewAI / LangGraph / Swarm | Механика оркестрации | Единица обмена — сообщение, не материал с ревизией; ни гейтов, ни прослеживаемости |
| Devin / SWE-agent | Суперрабочий: sandbox, long-horizon, playbooks | Один исполнитель вместо цеха; нет нормативной приёмки |
| Claude Agent Teams | Lead + параллельные инстансы, p2p | Авторитет = ведущий агент; их же research фиксирует сговор/саботаж в роях без внешних контрольных механизмов — прямой аргумент за внешние гейты |
| Text2BIM / AutoBIM / CAD-Llama | LLM→BIM/CAD генерация одного артефакта | Не производство: нет цехов, кандидатов, приёмочных органов |

**Вывод:** комбинация «рабочие столы + кандидаты + гейты + запечатанные
ревизии + replay + эффекты с чеками» не собрана ни у кого. Каждый сосед
имеет кусок. Переносимые уроки: из EDA — конвейер живёт на
форматах-контрактах и tool-based signoff, а не на суждении агента; из
deepseek-harness — append-only лог как принудительный рантайм-инвариант
(наш аналог: sealed revisions; стоит ужесточить из соглашения до
инварианта) и capability seams для замены целых цехов.

## 3. Как GDesign ложится на завод: набор цехов

Продукт завода = том проектной документации (4.3, КР3 и т.п.) с полной
прослеживаемостью каждого числа до пункта СП и исходных данных.

```text
FactoryRequest(new-design)
  -> W1 Discovery          изыскания, исходные данные, ТЗ, климатика/районы
  -> W2 Formalization      расчётная постановка: CANONICAL_SETUP (СК, оси,
                            DOF, знаки, сочетания) как контракт; CALC_TREE
                            как SRS; CALCULATION_MATRIX как UC/AC
  -> W-A Analysis (новый)  ячейки S2–S7: модель/нагрузки/РСУ/статика/моды/
                            постпроцессинг/фундамент; воркер готовит материал,
                            femdriver решает
  -> W-N Normative (новый) ячейки S8: проверки по пунктам СП с записью
                            пункта/редакции/запаса; clause-level fixtures
  -> W-D Drafting (новый)  S9: КР3-РР, эпюры, чертежи, PDF-комплект;
                            инвариант «каждое отображаемое значение =
                            трассируемый результат»
  -> Delivery              выпуск тома, сборка комплекта, подпись (человек),
                            архив; Git-тег релиза как локальный эффект
```

Существующие W1/W2/Delivery переиспользуются как есть. Три новых цеха —
декларативные пакеты в грамматике существующих (manifest + node protocols
+ contributions), без нового рантайма.

### 3.1. Новые MCP-инструменты (kernel-провайдеры, не LLM)

Ключевой принцип конвейера §20: воркер описывает желаемое состояние
текстом, но «текст не даёт эффекта или власти перехода». LLM не может
«нарисовать прочность» — она готовит материал, а считают и проверяют
детерминированные провайдеры с четырёхзначным исходом
(`passed|failed|unknown|error`):

| MCP-сервер | Роль в грамматике конвейера | Что делает |
|---|---|---|
| **femdriver-mcp** | CheckProvider | solve/modal/winkler/settlement; возвращает CheckReceipt с дайджестами, residuals, равновесием |
| **scad-witness-mcp** | CheckProvider (external witness) | экспорт модели, сравнение результатов против SCAD-эталона с явными маппингами; откалиброван по ADR-001 GDesign |
| **normbase-mcp** | versioned resource package | пункты СП/СНиП/ГОСТ с редакциями, формулы, допуски; запечатывается в манифест цеха (аналог PDK из EDA) |
| **cad-mcp** | EffectProvider + CheckProvider | генерация DXF/чертежей из результатов; проверка соответствия чертежа модели |
| **dockit-mcp** | EffectProvider | сборка PDF-тома (Word/fitz-путь), контроль полноты разделов |

Ни один из них не становится «вторым рантаймом» (§21: observation is not
another worker engine) — все регистрируются через tool-contributions пакета
цеха и работают через тот же шлюз authority.

### 3.2. Что уже готово в движке и переиспользуется без изменений

- **Atomic members at managed-document boundaries** (конец
  CONVEYOR-MENTAL-MODEL): том → раздел → пункт → величина — это ровно
  DocumentContainer/AtomicContractMember из ADR-053. Кардинальность
  замораживается при приёмке контейнера, downstream не выводит её заново.
- **Replay-капсулы = типовые серии.** Семейство опор параметризовано;
  капсулы, сертифицированные CellFinalAcceptance на эталоне, дают
  повторные прогоны семейства почти без модели (semanticInputDigest уже
  включает параметры и контракты). Это механизм серийного производства.
- **Человеческая граница как фича:** подпись ГИПа/экспертиза — честный
  `human_required` + approval в Delivery, не анонимная пауза. Для
  регуляторного рынка это продающий аргумент: завод не претендует на
  подпись, он даёт экспертизо-готовый материал.
- **Four-valued checks:** отсутствие femdriver-возможности/квалификации =
  `unknown`, не модельный «passed». GDesign уже живёт так («placeholder
  не может дать PASS-вердикт»).

## 4. Улучшения движка («сбитая опора»)

Чтобы метафора «транзисторы → CPU» сработала, инварианты должны быть не
декларацией, а принудительной физикой. По убыванию приоритета:

1. **Завершить ADR-053/073 cutover** (epic-scoped settlement →
   lifecycle-scoped; newest-wins биндер → semantic; resume-совместимость →
   с implementation-дайджестами). Без этого трассировка много-рановых
   инженерных проектов (типовые серии = много Factory Run одного Project)
   сломается на третьем ране — предсказание из конформность-аудита.
2. **Ввести первый класс «Regulated Domain Pack»:** versioned normative
   catalog + реестр квалифицированных провайдеров + unit registry
   (кН/м/МПа) с обязательной dimensional-проверкой на ingress. У GDesign
   это де-факто есть (SI + units на каждой API-границе) — поднять до
   платформенного механизма.
3. **Ужесточить sealed-revision до рантайм-инварианта** (урок
   deepseek-harness): всё, что видит модель, обязано реконструироваться
   из запечатанного материала — не соглашение, а проверка в рантайме.
4. **Witness-провайдеры как отдельный класс чеков:** внешний солвер (SCAD)
   — свидетель с явной model-parity квалификацией, не оракул. У GDesign
   это ADR-001; платформе нужен интерфейс «external witness receipt».
5. **Serie/runbook для типовых семейств:** формализация параметрического
   семейства → replay-капсулы → изменение параметров без новой формализации.
   Проверить fitness-тестами §25 на инвариант «новый параметр ≠ новый
   Project».

## 5. Бизнес-идея и продуктовая гипотеза

### 5.1. Инсайт

В ПО приёмку пришлось изобретать (тесты, ревью). **В инженерии приёмка уже
существует как институт** — нормоконтроль, экспертиза, СП/ГОСТ, подпись
ГИПа. Завод не меняет домен — он автоматизирует уже существующий конвейер
QC. Поэтому:

- барьер входа ниже (гейты не придумываем, они нормативные);
- ценность выше (прослеживаемость каждого числа — требование экспертизы,
  сегодня делается руками);
- ров глубже (формальная модель материала + приёмки не собрана ни у кого,
  см. §2).

### 5.2. Продуктовая гипотеза (проверяемая)

- **Кто:** малые проектные бюро ж-д/ПГС-профиля (5–50 инженеров), дефицит
  кадров, перегруз типовыми объектами (опоры, эстакады, фундаменты,
  малые мосты).
- **Боль:** типовое проектирование — 80% ручного труда по повторяющейся
  методике; сроки; ошибки → возвраты экспертизы; знания в головах.
- **Продукт:** «завод проектной документации»: параметрический вход
  (у GDesign — 7 параметров) → конвейер → экспертизо-готовый том с
  прослеживаемостью до пункта СП; двойной расчёт из коробки (ядро +
  SCAD-свидетель).
- **Канал/пилот:** одна ниша — опоры контактной сети/ОДН (GDesign уже
  доказал ядро: эталон MSK033742 в допуске 2.3% против SCAD, PDF-комплект
  35 страниц end-to-end). Продаём не «ИИ», а «том за часы вместо недель,
  готовый к экспертизе».
- **Монетизация:** подписка на завод + плата за том; on-prem (данные и
  расчёты чувствительны); позже — marketplace типовых серий (replay-капсулы
  как актив).
- **Unfair advantage:** replay + sealed revisions = воспроизводимость для
  аудита/экспертизы — то, что «суперагенты» структурно не могут дать.

### 5.3. Экономика рывка (транзистор → CPU)

Один воркер/агент = транзистор: что-то производит, ненадёжен, не
масштабируется качеством. Завод композиционен: replay-first
(детерминированность), sealed revisions (прослеживаемость), partition
invariance (восстановления не меняют результат), four-valued checks
(честность), carry-forward/continuation (не переделывать принятое),
obligation ledger (нет потерянных переходов). **Качественно новый продукт
возникает из композиции**: серия типовых опор с сертифицированными
капсулами стоит почти ноль токенов, а каждый том несёт доказательную
базу уровня экспертизы. Это недоступно ни Devin (один суперрабочий), ни
Factory.ai (нет модели материала), ни EDA (нет гибкости).

### 5.4. Риски и честные границы

- **Нормативная ответственность:** подпись остаётся за человеком; продукт
  — подготовка и доказательная база, не замена ГИПа. Это и правовая
  граница, и позиционирование.
- **Зависимость от квалификации солверов:** femdriver должен быть
  qualified dependency (GDesign-модель: 3–5 подтверждённых дефектов →
  пересмотр границы репозитория).
- **Завершённость cutover:** см. §4.1 — предусловие.
- **Валидация ниши:** до инвестиций в платформу — один реальный пилот на
  опорах (внешний заказ или собственный том на реальный объект).

## 6. Имя

Saga-mcp описывает механизм (MCP) и историю (Saga), не продукт. Кандидаты:

1. **OPORA** (рекомендую). Двойной смысл: инженерная опора (первый продукт
   буквально опоры) и опора/фундамент системы. Русское инженерное слово,
   произносимое на любом языке. Бэкроним:
   **O**rchestrated **P**roduction **O**f **R**egulated **A**rtifacts —
   «оркестрованное производство регулируемых артефактов» — ниша
   (regulated) заложена в имя.
2. **ZAVOD** — прямо и смело, но без второго смысла и плохо ищется.
3. **WERFT/Верфь** — красивая метафора (сложное изделие по чертежам с
   приёмкой Регистра), но уводит от ж-д/ПГС контекста.
4. **K-BYURO / КБ** — исторически точная метафора (ОКБ: журналы,
   нормоконтроль, военпред), но корпоративно безлико.

Имя — не главное (как справедливо отмечено); главное — что под ним стоит
формальная модель. Но OPORA связывает продукт, принцип и позиционирование
в одном слове.

## 7. Первые шаги (если развивать)

1. Закрыть материальный cutover (ADR-053/073 остатки) — предусловие.
2. Оформить GDesign-цеха как декларативные пакеты: W-A Analysis,
   W-N Normative, W-D Drafting (+ femdriver/scad/normbase/cad/dockit MCP
   как check/effect-провайдеры).
3. Прогнать эталон MSK033742 через завод end-to-end как L5 scripted E2E
   (нулевые токены, replay из зафиксированных капсул) — доказательство
   профессие-агностичности.
4. Один реальный пилот: параметрическое семейство 5–10 опор → серия томов
   → замер трудозатрат против ручного проектирования.
5. Решение по имени/позиционированию — после пилота, на цифрах.
