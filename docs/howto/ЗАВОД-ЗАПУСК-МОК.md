# Запуск завода на детерминированном моке

Мок заменяет ТОЛЬКО недетерминированный мозг (LM). Всё остальное — handlers, DB,
conveyor, gates, fences, provenance — реальное. Система не знает что работает на моке.

## Быстрый старт (одна команда)

```bash
npm run build && \
rm -rf .tracker.db* sim-workspace && \
mkdir -p sim-workspace && \
(cd sim-workspace && git init -b main && echo t>README.md && git add -A && \
 git -c user.email=sim@t -c user.name=sim commit -m i && git checkout -b dev) && \
export DB_PATH="$PWD/.tracker.db" && \
node -e "
const Database = require('better-sqlite3');
const db = new Database(process.env.DB_PATH);
const { SCHEMA_SQL } = require('./dist/schema.js');
db.exec(SCHEMA_SQL);
db.prepare('INSERT INTO projects (id, name, status) VALUES (1, ?, ?)').run('sim', 'active');
db.prepare('INSERT INTO epics (id, project_id, name, status) VALUES (1, 1, ?, ?)').run('bc', 'planned');
db.prepare('INSERT INTO repositories (id, name) VALUES (1, ?)').run('button-color-repo');
db.prepare('INSERT INTO project_repositories (id, project_id, repository_id, role, local_path, integration_branch, status) VALUES (1, 1, 1, ?, ?, ?, ?)').run('component', process.env.PWD + '/sim-workspace', 'dev', 'active');
db.close();
" && \
BASE=$(cd sim-workspace && git rev-parse HEAD) && \
sed -i \"s/expectedBaseCommit:.*/expectedBaseCommit: '$BASE',/\" scripts/sim-launch.mjs && \
node scripts/sim-launch.mjs && \
export SAGA_SIM_SCENARIO="button-color" && \
export SAGA_PRODUCT_LIFECYCLE_COMPOSITION="D:\\Development\\saga-mcp\\product-lifecycle-composition.mjs" && \
LAUNCH_REF=$(cat saga-launch-ref.txt) && \
SAGA_CLAUDE_PATH='node D:\Development\saga-mcp\tools\claude-cli-simulator.mjs' \
timeout 120 node dist/orchestrate-cli.js --launch-ref=$LAUNCH_REF
```

## Что происходит

1. Свежая DB (`.tracker.db`) инициализируется со schema
2. Создаётся проект, epic, git-репозиторий (`sim-workspace/`)
3. `scripts/sim-launch.mjs` создаёт factory order + launch request с правильным lifecycle input
4. `orchestrate-cli` запускается с `SAGA_CLAUDE_PATH` → симулятор вместо Claude CLI
5. Завод проходит: Discovery → Formalization → Development

## Переменные окружения

| Переменная | Значение | Назначение |
|-----------|----------|------------|
| `DB_PATH` | `$PWD/.tracker.db` | Путь к SQLite DB |
| `SAGA_CLAUDE_PATH` | `node D:\...\claude-cli-simulator.mjs` | Замена Claude CLI |
| `SAGA_SIM_SCENARIO` | `button-color` | Сценарий (golden path) |
| `SAGA_PRODUCT_LIFECYCLE_COMPOSITION` | `D:\...\product-lifecycle-composition.mjs` | Composition overrides |

## Уровень мока

Мок вставляется на ОДНОМ уровне — subprocess spawn. Симулятор получает тот же
prompt, тот же MCP config, те же env vars, тот же stdin, что и настоящий Claude CLI.
Он выдаёт тот же stream-json формат. Он вызывает ТЕ ЖЕ MCP handlers.

Runtime не видит разницы. Нет `SAGA_SIM_SCENARIO` проверок в runtime коде.
