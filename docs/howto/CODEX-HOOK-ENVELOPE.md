# Как отправить сообщение в активную сессию Codex через хук

Инструкция описывает проверенный способ впрыснуть контекст в работающую
сессию Codex (CLI или UI над CLI) **без перезапуска сессии и без остановки
завода**.

## Когда использовать

- AGENTS.md грузится один раз при старте сессии и **не перечитывается**
  (подтверждено оф. докой и GitHub issue #8547). Для уже идущей сессии
  правка AGENTS.md бесполезна.
- Хук `UserPromptSubmit` впрыскивает контекст в **каждый следующий turn**
  агента → гарантированно доставляет сообщение в активную сессию.

## Официальная документация

- **Codex Hooks — официальная дока:** https://learn.chatgpt.com/docs/hooks
- События: `SessionStart`, `UserPromptSubmit`, `PreToolUse`, `PostToolUse`,
  `Stop`, `notify`
- Конфиг: `~/.codex/hooks.json` (глобально) или `.codex/hooks.json` (per-repo)
- `additionalContext` (plain stdout или JSON) впрыскивается без остановки
- `decision: block` или exit code 2 — блокируют; **НЕ использовать, если
  нельзя останавливать работу агента**

## Что уже готово (не нужно пересоздавать)

| Файл | Назначение |
|---|---|
| `C:\Users\user\.codex\hooks\envelope-reminder.mjs` | Скрипт-инжектор. Читает `AGENT-ENVELOPE.md` из `cwd` сессии, проверяет секцию «Исходящие сообщения», и если ответа нет — печатает JSON с `additionalContext` (напоминание прочитать ADR-053 + ответить в конверт). Никогда не блокирует. |

## Как снова включить хук (3 шага)

### 1. Убедиться, что `AGENT-ENVELOPE.md` существует в корне репо

```bash
ls -la D:/Development/saga-mcp/AGENT-ENVELOPE.md
```

Если нет — создать (шаблон ниже в приложении).

### 2. Создать `~/.codex/hooks.json`

```json
{
  "UserPromptSubmit": [
    {
      "hooks": [
        {
          "type": "command",
          "command": "node \"C:\\Users\\user\\.codex\\hooks\\envelope-reminder.mjs\""
        }
      ]
    }
  ]
}
```

### 3. Проверить локально (без запуска Codex)

```bash
echo '{"cwd":"D:\\Development\\saga-mcp"}' | node "C:/Users/user/.codex/hooks/envelope-reminder.mjs"
```

Ожидаемое поведение:
- Если в секции «Исходящие сообщения» в `AGENT-ENVELOPE.md` **пусто** →
  скрипт печатает JSON с напоминанием.
- Если агент уже ответил → скрипт печатает пустой stdout, exit 0.

Хук применяется **следующим turn'ом** агента — без перезапуска сессии.

## Как выключить хук

```bash
rm ~/.codex/hooks.json
```

Скрипт `envelope-reminder.mjs` оставить — он понадобится в следующий раз.

## Как поменять текст напоминания

Скрипт хранит текст напоминания в массиве строк в функции (const reminder = [...]).
Отредактируй строки между `──── ВСТАВЛЕННОЕ НАПОМИНАНИЕ ОПЕРАТОРА ────` и
последней линией `────────────────────────────────────────────────────────`.

## Как адресовать другой файл / вопрос

В `envelope-reminder.mjs` заменить:
- путь к файлу (по умолчанию `AGENT-ENVELOPE.md` в `cwd`)
- имя секции для проверки ответа (по умолчанию `## Исходящие сообщения`)
- текст напоминания

## Безопасность

Скрипт:
- **не блокирует** (нет exit code 2, нет `decision: block`)
- **не мутирует** файлы (только читает `AGENT-ENVELOPE.md`)
- **не трогает** заводскую БД, sandbox, процессы
- молчит, если ответ уже дан
- игнорирует malformed JSON на stdin (баг Windows, issue #23784)

## Приложение: шаблон AGENT-ENVELOPE.md

```markdown
# AGENT-ENVELOPE — общий канал связи между агентами

## Входящие сообщения (оператор → агенты)

### <ДАТА> — от ОПЕРАТОРА — агенту
<текст просьбы — что прочитать, куда ответить, какие вопросы>

## Исходящие сообщения (агенты → оператору)

<!-- Агент: пиши свой ответ сюда, ниже этой строки. Не удаляй чужое. -->
```
